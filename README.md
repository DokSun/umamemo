# 우마 메모

**우마무스메 육성 중 서포트 카드 이벤트 진행도를 기록하고, 메모장 등 보조 기능을 함께 사용할 수 있는 웹 도구입니다.**

**바로 사용하기:** https://doksun.github.io/umamemo/

별도의 설치 없이 브라우저에서 사용할 수 있습니다.

## 현재 제공 기능

### 서포트 이벤트 카운팅

- 서포트 카드 **6장**을 선택하고, 카드별 이벤트 진행 상황을 기록합니다.
- 일반 서포트 카드: 연속 이벤트 **1~3**, 랜덤 이벤트 **A / B**
- 친구 카드: 연속 이벤트 **1~5**
- 그룹 카드: 이벤트 단계 수를 **1~5** 중 직접 선택
- 이미지를 눌러 카드 선택 창을 열 수 있습니다.
- 카드 선택 창은 **스피드·스태미나·파워·근성·지능·친구·그룹** 속성과 **SSR / SR / R** 등급으로 필터링할 수 있습니다.
- **이벤트 카운팅 초기화** 옆의 **초기화 팝업** 스위치로 확인창 표시를 ON/OFF 할 수 있습니다. 기본값은 ON이며 설정은 저장됩니다. OFF일 때는 확인창 없이 이벤트 진행 기록만 초기화합니다.
- **한국 / 일본 서버 모드**를 구분합니다. 한국 모드에서는 한국 서버 출시일 기준으로 카드 목록을 제한합니다.

> 이 도구의 숫자 버튼은 진행 여부를 기록하는 용도입니다. 실제 이벤트의 이름이나 개별 효과를 표시하는 기능은 아닙니다.

### 스케줄표 (프로토타입)

- **주니어·클래식·시니어 모두 1월~12월 24턴(각 24칸)**을 4열 격자로 표시합니다. 주니어 1~6월에는 동일한 구분 테두리를 적용합니다. 해당 구간에 등록된 목표 레이스는 별도로 표시하며 수정할 수 없습니다.
- 각 칸에서 **훈련 5종(스피드·스태미나·파워·근성·지능), 휴식, 외출(친구 아이콘), 레이스** 중 하나를 기록하거나 비울 수 있습니다. 목표 레이스는 캐릭터 DB에서 자동으로 고정 표시되며 수동으로 선택할 수 없습니다. 훈련 5종과 외출은 기존 서포트카드의 속성 아이콘을 재사용하며, 나머지는 임시 아이콘입니다.
- **스케줄표 단독 사용 시 작업 영역이 충분히 넓으면 3개 시기를 가로로 나란히 표시**합니다. 좁은 화면과 동시 사용에서는 탭으로 한 시기씩 전환합니다.
- 시나리오 전용 아이콘을 나중에 추가할 수 있도록 행동 데이터에 **공통/시나리오 전용 등록 구조**를 두었습니다.
- 기존 주니어 18칸으로 저장된 계획은 24칸 일정으로 자동 변환해 기존 4~12월 기록을 유지합니다. 이전 버전의 포괄적인 훈련·보건실·기타 아이콘은 기존 기록에서만 유지되며, 새로운 행동 선택 목록에서는 제외됩니다.
- 현재 스케줄은 자동 저장되며, 별도 **계획 관리**에서 이름을 붙여 최대 50개의 계획을 저장·불러오기·덮어쓰기·이름 변경·삭제할 수 있습니다.
- 불러온 계획은 현재 작업본으로 복사되므로 계획 원본은 자동 변경되지 않습니다.
- **일본 서버 캐릭터 135명**을 중복 없이 기본 한국어 이름으로 표시합니다. 다른 의상·별칭은 목록에 별도로 표시하지 않으며 기본 의상 육성 목표를 사용합니다.
- 목표 레이스 칸은 **수정 불가**이며 클릭하면 목표 정보만 볼 수 있습니다. 글로벌 서버의 영어 배너를 제거하고, 한국어 레이스명과 등급이 적힌 자체 배너를 표시합니다. 데뷔전은 모든 캐릭터에서 공통 한국어 배너 ID 9002를 사용하고, 다른 목표 레이스는 해당 레이스 ID로 GameTora 한국어 배너를 표시합니다. 이미지가 없으면 자체 한국어 배너로 대체합니다.
- 레이스 DB의 ID를 목표 레이스와 연결해 배너 파일을 조회합니다. 레이스 배너 이미지 파일은 직접 저장하지 않고 외부 이미지 URL을 사용합니다.
- 캐릭터 DB는 **일본 서버 기준**입니다. 원본 의상별 272종을 캐릭터별 135명으로 통합했으며, 이전에 선택한 의상 ID도 기본 캐릭터와 연결할 수 있도록 보존합니다.
- 레이스 정보도 일본 서버 데이터 **404개 개최 일정**으로 교체했습니다. 레이스 선택 목록은 한국어 번역 사전을 적용하며, 개최 시기·등급·거리·경기장은 저장된 JSON에서 조회합니다. 주니어 7월 전반까지는 데뷔전 이외의 레이스를 지정할 수 없습니다.
- 데이터 출처: GameTora 기반 [UmaTools 공개 데이터](https://github.com/daftuyda/UmaTools). 우마 메모는 **`data/schedule_jp.json`을 직접 읽으므로 외부 사이트의 응답·CORS에 의존하지 않습니다.** `scripts/update-schedule-jp.mjs`와 GitHub Actions로 원본 변경 사항을 주기적으로 반영합니다. 외부 출처 데이터는 업데이트 지연·누락이 있을 수 있습니다.
- 단독 사용과 카운팅 동시 사용이 가능하며, 동시 사용 시 **통합 초기화**로 현재 일정과 이벤트 진행을 함께 지웁니다. **저장된 계획은 삭제되지 않습니다.**
- 현재 스케줄과 계획은 한국·일본 서버 모드마다 별도 저장됩니다.

### 메모장

- 자유롭게 텍스트를 기록할 수 있는 별도 기능입니다.
- 입력 내용은 자동 저장되며, **메모장 초기화** 버튼을 사용해 메모 내용만 지울 수 있습니다.
- 카운팅 초기화와 메모장 초기화는 서로 독립적입니다.

### 화면 및 도구 관리

- 왼쪽 위 **☰ 기능** 버튼을 누르면 화면 왼쪽에서 사이드 메뉴가 열립니다. 여기서 사용할 도구를 선택합니다.
- **동시 사용 OFF:** 선택한 기능을 단독으로 표시합니다.
- **동시 사용 ON:** 이벤트 카운팅과 보조 기능을 나란히 표시합니다.
- 동시 사용 시 **5:5 / 6:4 / 7:3** 화면 비율을 선택하고 **좌우 전환**할 수 있습니다.
- 좁은 화면에서는 패널을 세로로 배치합니다.
- 초기화 버튼은 각 기능 패널의 맨 아래에 있습니다.
- 추후 육성 기록형 보조 기능을 추가할 수 있도록, 도구별 초기화 범위를 구분하는 구조로 구성했습니다.

## 데이터 저장 및 이미지

- 카운팅 기록, 메모, 현재 스케줄 및 저장된 계획, 서버 선택 및 화면 설정은 **브라우저의 로컬 저장소(localStorage)**에 저장됩니다.
- 한국 서버와 일본 서버의 카운팅 기록은 서로 구분됩니다.
- 서포트 카드 이미지는 **외부 이미지 URL**을 통해 표시합니다. 카드 이미지 파일 자체를 저장소에 포함하지 않습니다.
- 외부 이미지 제공처가 변경되거나 접근할 수 없는 경우에는 일부 이미지가 표시되지 않을 수 있습니다.
- 브라우저 저장 데이터를 삭제하거나 다른 브라우저·기기에서 접속하면 저장 기록이 이어지지 않을 수 있습니다.
- 이미지의 저작권은 각 권리자에게 있습니다.

## 사용 방법

1. https://doksun.github.io/umamemo/ 에 접속합니다.
2. 왼쪽 **☰ 기능** 메뉴에서 **한국 / 일본 서버**를 선택합니다.
3. 서포트 카드 이미지 영역을 눌러 6장의 카드를 편성합니다. 스케줄표는 **☰ 기능**에서 선택합니다.
4. 육성 중 진행한 이벤트 번호 또는 A / B 버튼을 눌러 기록합니다.
5. 필요한 경우 **☰ 기능**에서 메모장을 단독 또는 동시 사용합니다.
6. 새 육성을 시작할 때는 이벤트 카운팅 패널 아래의 **초기화** 버튼으로 진행 기록을 지웁니다.

## 개발 및 배포

이 프로젝트는 별도 빌드 과정이 없는 HTML, CSS, JavaScript 기반의 정적 웹사이트이며 **GitHub Pages**로 배포됩니다.

- `index.html`: 페이지 구조
- `style.css`: 화면 및 카드 선택 UI
- `app.js`: 도구 상태 관리, 이벤트 카운팅과 저장 처리
- `data/support_cards.json`: 서포트 카드 데이터
- `data/image_sources.json`: 외부 이미지 URL 목록
- `data/schedule_jp.json`: 일본 서버 기준 캐릭터·목표 레이스·레이스 일정 (자동 갱신)
- `data/character_ko_names.json`: 캐릭터 및 의상 별칭 한국어 번역 표
- `data/race_ko_names.json`: 레이스명 한국어 표기 사전 (부분 적용)
- `scripts/update-schedule-jp.mjs`: 일본 서버 DB 갱신 시 한국어 번역과 목표 레이스 상세 정보 유지
- `docs/tool-architecture.md`: 도구 구조 및 초기화 규칙

데이터 JSON 파일을 불러와야 하므로 로컬 실행 시에는 `index.html` 파일을 직접 여는 대신 **로컬 HTTP 서버**를 사용하세요.

과거 초기 버전은 `archive/v1.0.0-initial` 브랜치에 보존되어 있습니다.
